# 5 分钟 Up/Down 市场结算规则（实证文档）

> 版本：v1.0 ｜ 日期：2026-09-12 ｜ 状态：**方向性规则已钉死；精确 TWAP 数值待 pm-record 复核**
> 产出依据：Gamma 市场 description 原文（一手）+ 578 个已结算窗口实证（scripts/settlement_study.py）

---

## 1. 规则定义（一手来源）

Gamma 市场 `description` 原文（btc-updown-5m-*，2026-09-12 拉取，eth 同款措辞）：

> This market will resolve to "Up" if the time-weighted average price (TWAP) of
> Bitcoin, generated by Chainlink, of the time range specified in the title is
> **greater than or equal to** the price at the beginning of that range.
> Otherwise, it will resolve to "Down". The resolution source ... is the
> BTC/USD TWAP data stream available at
> https://data.chain.link/streams/btc-usd-twap-60s-streams.

钉死的要点：

| 项 | 结论 |
|---|---|
| 判定 | **窗口时段 TWAP ≥ 窗口起点价格 → Up；否则 Down**（注意是 ≥，含相等） |
| 结算源 | Chainlink Data Streams `XX/USD TWAP-60s`（经 Polymarket RTDS 中继，非链上聚合器） |
| 结果获取 | Gamma `/markets?slug={sym}-updown-5m-{ws}&closed=true` 的 `outcomePrices`（`"1"` = 赢）。**查询已结算市场必须带 `closed=true`**，不带/带 `false` 均返回空（历史排查卡点即此） |
| `umaResolutionStatus` | 结算完成后为 `"resolved"`，可用作结算完成判据 |

## 2. Taker fee（官方文档确认，影响 PnL 口径）

来源：https://docs.polymarket.com/trading/fees.md（2026-09-12 拉取）

```
fee = C × feeRate × p × (1 - p)        # C=成交份数, p=成交价
```

| 项 | 结论 |
|---|---|
| Crypto 类 feeRate | **0.07**（与 Gamma 市场字段 `feeSchedule: {rate: 0.07, exponent: 1, takerOnly: true, rebateRate: 0.2}`、`takerBaseFee: 1000` 一致） |
| 收费对象 | **仅 taker**；maker 永远免费 |
| 舍入 | 5 位小数；最小收费见官方 Fee Precision 节 |
| 例 | 100 股 @ $0.28 → fee = 100×0.07×0.28×0.72 ≈ $1.41 |
| Rebate | taker 可经 Taker Rebate Program 退回部分（retail 口径忽略，保守不計） |

对策略的影响（$2 名义、入场 ≈0.28、止盈 0.65 卖出）：

- 买入 fee ≈ 名义 × 0.07 × (1−p) ≈ $0.10；卖出 fee ≈ $0.11 → 单笔往返 ≈ $0.21（约名义的 10%）
- **止盈 0.65 的净到手 ≈ 0.65 × (1−0.0455) ≈ 0.62**；回测 EV 必须含此口径
- 赎回（redeem $1/份）官方费用文档未提及收费 → 暂按免费，标注**待链上实测确认**

## 3. 实证方法与结果

方法：Binance 5m K 线（data-api.binance.vision）作窗口价格路径**代理**，对
近 24h 全部已结算 btc+eth 5m 窗口验证候选规则 `close >= open` 的方向一致率。
Binance 现货与 Chainlink TWAP 存在交易所价差，分歧应集中在近平窗口——
若结构不符（如分歧随机分布）则说明规则理解有误。

结果（2026-09-12 运行，样本 `runtime/settlement_samples.json`）：

```
样本：578 个已结算窗口（btc, eth，近 24h）    跳过：0

R_close  close>=open          一致 489/578 = 84.6%
按窗口平坦度 |close-open|/open 分桶：
  <0.02%   n=130  一致率 56.9%
  <0.05%   n=150  一致率 84.0%
  <0.1%    n=133  一致率 95.5%
  <0.5%    n=153  一致率 98.0%
  >=0.5%   n=12   一致率 100.0%
```

**判读**：结构与预期完全吻合——分歧随窗口变平单调恶化，非平坦窗口接近全对。
84.6% 的总体一致率是**代理数据源价差**的下限值，不是规则错误的证据。

## 4. 对回测的使用口径（铁律）

1. **结算标签（赢/输）一律以 Gamma `outcomePrices` 为权威**——有交易/有回填的窗口不使用任何推导；
2. 规则推导（从录制 TWAP 推结算）仅用于**无回填的窗口**，且必须标注"推导值"；
   平坦度 <0.1% 的窗口推导不可信（一致率 <96%），推导置信度按分桶表衰减；
3. 所有 PnL 计算含 taker fee（第 2 节公式）；maker 免费是做市方向的后备优势；
4. **未决事项**（pm-record 上线后复核）：
   - 用 RTDS `full_accuracy_value` 直接复核 TWAP 数值与"起点价"的取值口径（窗口首样本 or 前窗末值）；
   - redeem 是否免费，链上赎回一笔实测。
