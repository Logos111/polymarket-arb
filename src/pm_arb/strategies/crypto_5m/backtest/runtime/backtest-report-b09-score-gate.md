## TL;DR

| 发现 | 证据 | 结论 |
|---|---|---|
| **门控方向正确：score≥1 大幅减亏** | 验证段 vs 基线：BTC per -0.1734 → -0.0876（减亏 49%）、ETH -0.2091 → **+0.0166**（扭亏） | 评分 v2 至少有效剔除了 score=0 的最差入场（入场数削减 ~50%） |
| **未达上线纪律：胜率不"清晰"超线** | 合并两币验证段 score=1：n=1,014，胜率 ≈27.9%，仅超 27% 盈亏线 0.9pp（<1 SE）；合并 per ≈ -0.030 仍负 | **min_reversal_score 维持 None，不进实盘**（纪律执行） |
| **score=1 是唯一稳健阈值** | score≥2 起两币单调恶化（ETH 2→7：-0.1067 → -0.4574）；score=7 BTC +0.5539 为 n=35 小样本噪声 | 高分≠高胜率：深跌形态路径收益高但结算胜率仅 ~29% |
| **校准泄漏必须声明** | 评分 v2 阈值在**全量数据**（含验证段）上标定 | 本轮验证段结果已是高估；真实 OOS 只会更差 |

## 2. 解读

- **score=0 入场是最差的入场**：门控关闭时基线验证段 per -0.17 ~ -0.21，score≥1 滤掉约一半入场后两币同步改善——评分 v2 的排序能力在回测口径下成立（这正是批次 1/2 分桶的预期转化）。
- **更高阈值反而更差**（ETH 清晰单调）：reversal_score 高分集中于"深跌 + 动能未衰竭"形态——批次 2 已证明该形态**路径收益**（ret60 +0.16~+0.30）远强于**结算胜率**（29%）。持有到结算（tp=0.99）口径下高分样本并未更接近结算翻正，反而样本越筛越偏、N 缩小方差放大。**评分排序的是路径，不是结算**——这是本轮最重要的机理结论。
- **score=7 BTC +0.5539**：n=35、ETH 同阈值 -0.4574，典型小样本噪声，不作任何信号解读。

## 3. 上线判定（对照既定纪律）

纪律原文（批次 0 报告 §7）："验证段胜率清晰超 27% 盈亏平衡线才谈上线"。

- BTC score=1：27.4%（n=456，SE≈2.1%）
- ETH score=1：28.3%（n=558，SE≈1.9%）
- 合并：≈27.9%（n=1,014，SE≈1.4%）——超出盈亏线 0.9pp，<1 SE，**不构成"清晰超线"**
- 合并 per ≈ -0.030：扣费前仍为负

**判定：不达标。`min_reversal_score` 默认值维持 `None`（门控关闭），实盘路径零改动。** 门控代码与参数已就位，后续任何一轮证据达标只需改 `score_weights.json` / 参数覆盖即可启用。

## 4. 限定（必读，本轮新增两条）

- **校准泄漏**：评分 v2 的阈值（ud_delta_deep=0.15、obi_improve=0.5、thin_depth=0.27、momentum_flat=0.0001）标定自全量分桶（含本轮验证段数据）——本轮"验证段"并非真正 OOS，门控效果被系统性高估；
- **单遍网格小样本**：门控组每 tick 计算全套特征，全网格为单次运行，无重复采样置信区间；
- 沿用前轮：outcome 为推断值、中价口径未含费滑、胜率与路径收益分叉未解决。

## 5. 引擎改动（本轮代码交付）

- [engine.py](../engine.py)：`replay_ticks` 接门控（`WindowFeatureBufs` 自窗口首 tick 推进 + `decide_entry_v2`；`capture=None` 且 `min_reversal_score=None` 时与旧版逐字节一致）；`replay_window`/`run_grid` 构造 `twap_seq`
- [run.py](../run.py)：门控 + 无 --spot 时 fail-fast 断言（否则 fail-closed 零入场静默）
- [grid.py](../grid.py)：轴换为 `min_reversal_score ∈ {None, 1..7}`，固定参数取 b07 最优
- 测试：4 项门控测试（含 score=5 合成场景精确入场、基线零回归、无 spot fail-closed、门控关闭路径不变），全量 **192 passed** + ruff 干净

## 6. 下一步（按依赖顺序）
