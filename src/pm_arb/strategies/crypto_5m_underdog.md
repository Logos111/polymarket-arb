# 策略：BTC/ETH 5 分钟冷门方方向性交易（crypto_5m_underdog）

> 状态：实验性（小额真实资金验证）｜实现：`src/pm_arb/app/trade5m.py`
> 类型：**方向性投机，不是套利**。预期胜率低于 50%，靠 +100% 止盈与结算赔付管理盈亏比。

## 1. 标的

Polymarket 5 分钟加密 Up/Down 二元市场（Chainlink 结算）：

- slug 规则：`{sym}-updown-5m-{window_start_unix}`，窗口起点为 UTC 时间向下取整 300 秒
- 每窗口两个 token：**Up** / **Down**，结算时正确方向每份赎 $1，错误方向归 $0
- 支持：btc / eth（代码层发现支持 sol/xrp/doge/bnb/hype/zec，CLI 仅开放 btc/eth）

## 2. 交易规则（用户确认的固定参数）

| 参数 | 值 | 含义 |
|---|---|---|
| `TARGET_NOTIONAL` | $2.00 | 单笔名义金额；份数 = ceil(2/ask)，不低于市场 orderMinSize |
| `ENTRY_AFTER` / `ENTRY_UNTIL` | 105s / 135s | 开窗后第 105–135 秒（剩余 3:15–2:45）一次性判定入场 |
| `MAX_ENTRY` | 0.30 | 冷门方 best ask 必须 < 0.30（30 点以下） |
| `MAX_VOL` | $25 | 本窗口 Chainlink 价格 high−low 必须 < $25 |
| `TAKE_PROFIT_RATIO` | 2.0 | best bid ≥ 成本 ×2.0 时市价卖出（+100%） |
| 退出兜底 | 持有到结算 | 未触发止盈不再操作，对赎 $1 / 归 $0 |
| 下单方式 | FOK | 全部成交或立即取消，杜绝腿风险与挂单残留 |

**选边**：买入双边中更便宜（ask 更低）的一方，即市场认为概率较小的"冷门方"。

两个过滤条件需**同时满足**：窗口已走过的 105–135 秒内价格几乎不动（高低点 < $25），
且冷门方仍只要 < 30¢。逻辑是：低波动下冷门方报价可能过度悲观，而剩余约 2.5 分钟内
价格朝冷门方向漂移就能让低价 token 翻倍；不满足则放弃本窗口，自动等下一窗口（默认最多 3 个）。

> 参数迭代：初版为 90–120s 入场 / $20 波动 / +50% 止盈，首跑 3 窗口全部被 $20 过滤拦截
> （实测 $32–43），2026-09-09 放宽为现行参数（105–135s / $25 / +100%）。

## 3. 价格源：为什么用链上 Chainlink 而不是盘口

- 5min Up/Down 市场**按 Chainlink XX/USD 聚合器价格结算**（Polygon 主网），
  预测标的与结算标的必须同源，否则任何信号都有基差风险
- BTC：`0xc907E116054Ad103354f2D350FD2514433D57F6f`（8 位小数）
- ETH：`0xF9680D99D6C9589e2a93a78A04A279e509205945`
- 轮询 `latestRoundData()`（selector `0xfeaf968c`），每 2s 一次，进程内记录窗口 high/low
- RPC 默认 `https://polygon-bor-rpc.publicnode.com`（`polygon-rpc.com` 已 401，见 `.env.example`）
- 盘口价格（Up/Down 双边 best bid/ask）仍来自 CLOB REST `/book`，同周期轮询

## 4. 执行流程

1. 睡到下一个干净 5 分钟窗口起点（保证高低点从 t=0 完整记录）
2. Gamma 按 slug 发现当前窗口市场，读取 orderMinSize、enableOrderBook
3. t∈[0, 280s) 每 2s：拉 Chainlink 价格 + 双边盘口，维护 high/low 并打印轨迹
4. t∈[105,135s] 做一次入场判定；FOK 买入冷门方
5. 持仓后轮询 best bid，触达 +100% 则 FOK 卖出；否则持有到窗口结算
6. 结算前 20s（`END_MARGIN`）停止一切操作

## 5. 风险

- **全损**：冷门方结算错误时整笔名义金额归零（$2 设计为可接受的学费）
- **止盈单 FOK 失败**：盘口抽薄时卖单可能不成交，代码会下轮继续尝试，最终仍可拿结算
- **波动过滤被操纵风险**：Chainlink 在窗口内可能长时间不更新（heartbeat），
  high-low 偏小不代表真实低波动；这是本策略最脆弱的假设
- **窗口间隙**：市场创建/关闭瞬间 Gamma 查不到，自动跳过
- 赔率 < 0.30 本身意味着市场隐含胜率 < 30%，+100% 止盈不改变到期期望，
  只改变实现路径；长期期望为负（含价差），**仅作小额验证，不构成可规模化策略**

## 6. 使用

```bash
# 只看不交易（观察一个窗口的过滤判定与轨迹）
PYTHONPATH=src python -m pm_arb.app.trade5m --symbol btc --dry-run --windows 1
# 真实 $2 交易，最多尝试 3 个窗口
PYTHONPATH=src python -m pm_arb.app.trade5m --symbol btc --windows 3
```

需要 `.env`：`PM_PRIVATE_KEY`（小额专用 EOA 钱包）、网络受限时 `PM_PROXY_URL`、
`PM_PRICE_FEED_RPC_URL`。L2 API key 留空时由私钥自动派生。

## 7. 实盘验证记录

### 2026-09-09 首次实盘跑批（3 窗口，未成交，$0 盈亏）

命令：`python -m pm_arb.app.trade5m --symbol btc --windows 3`（真实凭证、FOK 通道就绪）。

| 窗口 (UTC) | t+90~120s Chainlink range | 冷门方 ask | 判定 |
|---|---|---|---|
| 8:05–8:10 ET | $39.59 | 0.001（Down，盘口单边） | ❌ 波动超限 |
| 8:10–8:15 ET | $32.38 | 0.010（Up） | ❌ 波动超限 |
| 8:15–8:20 ET | $43.39 | 0.001（Up） | ❌ 波动超限 |

三窗口均未通过 `range < $20` 过滤，系统未发出任何订单（$2 资金未动用）。

复盘要点：

- **过滤实际很严格**：Chainlink 每个 heartbeat 更新一次，单次跳动常达 $30–40，
  90 秒内只出现 2–3 次更新也足以让 high-low 超 $20。需要明显更平静的盘面才会入场；
  第 2 窗口 t+49s 时 range 曾为 $19.09，临近阈值但 t+72s 一次跳动即破线。
- **冷门方流动性假象**：窗口前段热门方方向已很明确时，冷门方经常只有 bid、
  没有 ask（best_ask=n/a），实际可买价出现在 0.001–0.01 的极端位置；
  即便波动过滤通过，也要确认 ask 真实可成交且份数 ×ask 名义金额有意义
  （当前 `ceil(2/ask)` 在 ask=0.01 时会算出 200 份、名义 $2，止盈需 bid 回到 0.015）。
- 工程验证：L2 凭证自动派生、Chainlink 直连轮询、双边盘口、引导重试、
  窗口末段 404 容错均按预期工作；代理（Clash）中途有过约 1 分钟断流，重试逻辑覆盖。
- 后续观察：可在低波动时段（亚洲凌晨/周末）再跑批收集入场样本；
  或用录制的 tick 数据回测 `$20` 阈值在历史窗口的通过率，再决定是否放宽（如 $30）。
